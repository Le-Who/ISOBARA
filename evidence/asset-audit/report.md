# Аудит игровых WebP-иконок

Проверены все 12 файлов `public/assets/*.webp`: сделан визуальный contact sheet на светлом и тёмном фоне и измерены альфа-маски. Метрики используют порог `alpha >= 16`; компоненты считаются по 8-связности. Наличие alpha-канала само по себе не считалось признаком корректного вырезания. Полные численные данные лежат в [measurements.json](measurements.json), визуальный лист — [contact-sheet-light-dark.png](contact-sheet-light-dark.png).

| Файл | Наблюдение |
|---|---|
| `cloak.webp` | Верх и правая сторона силуэта упираются в холст: 62 и 49 пикселей на краю. Плащ обрезан. Выбран для ремонта. |
| `coil.webp` | Видна отдельная деталь снизу (857 px); alpha касается низа (60 px). |
| `fork.webp` | Основной силуэт цел; на light/dark листе отдельная обрезанная часть не подтверждена. Цветные пиксели из сырого прозрачного просмотра не классифицированы как доказанный дефект вырезки. |
| `furnace.webp` | Посторонний фрагмент снизу/справа (1180 px), alpha касается нижнего края (58 px). |
| `gauge.webp` | Видимого среза или посторонних деталей нет; отступы от всех краёв сохранены. |
| `orb.webp` | Основной предмет цел; 5 threshold-пикселей у нижнего края и компонент размером 5 px. |
| `prism.webp` | Несколько осколков снизу (250/114/29 px); alpha касается нижнего края (53 px). |
| `rotor.webp` | Ротор срезан сверху и слева (59/47 краевых пикселей); слева отдельный фрагмент (579 px). Выбран для ремонта. |
| `seed.webp` | Стеклянный корпус касается верхнего края (93 px), зазор сверху отсутствует. |
| `tonic.webp` | Три посторонних фрагмента снизу (474/267/169 px); alpha касается верхнего и нижнего краёв. |
| `vest.webp` | Силуэт цел и не касается холста; сырые цветные пиксели края не засчитаны как подтверждённый дефект без проявления на двухфоновом осмотре. |
| `void.webp` | Верхняя часть касается края (53 px), сверху нет запаса. |

Для двух выбранных предметов генерация выполнена встроенным `image_gen`, по одному предмету на вызов, с прозрачным фоном и локальной ссылкой на исходную иконку. PNG-источники и lossless WebP-кандидаты находятся в `output/assets/equipment-repair/`; их промпты, точные returned paths и SHA-256 сохранены в `provenance.json`. Исходные `public/assets` и игровые файлы не менялись.

После генерации оба предмета визуально проверены на светлом и тёмном фонах в [candidates-light-dark.png](../../output/assets/equipment-repair/candidates-light-dark.png). У обоих кандидатов полные силуэты, нет касания краёв и отдельных фрагментов; WebP-кандидаты содержат по одной компоненте при пороге alpha 16. PNG-источники оставлены полноразмерными; кандидаты уменьшены целиком без кадрирования до максимального ребра 384 px и сохранены как lossless WebP. Фактический запас у плаща — 3,0–4,9%, у ротора — 3,1–8,9% (меньше целевых 10–15%, но все края свободны и силуэт не обрезан).

`cloak` соответствует высокоредкой оболочке в `src/core/progression.ts`; `rotor` — инструменту Аэролога. Использования в `src/core/content.ts` описаны в provenance. Модель генерации не указывается: встроенный инструмент не подтвердил её идентификатор.
