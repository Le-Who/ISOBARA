# Необязательные сетевые копии

В 2.1 игра по-прежнему запускается без Node, аккаунта и сети. Дополнительный пункт «Сетевая копия» ничего не отправляет при открытии. Для операции нужны адрес отдельно запущенного сервиса и явное нажатие игрока. Общего публичного сервера в поставке нет.

## Игроку

1. Откройте «Сетевая копия» на титульном экране или в паузе.
2. Укажите адрес сервиса (HTTPS; HTTP допустим только для локального теста на localhost).
3. Нажмите «Создать новую копию». После подтверждения сервера сохраните **адрес и код ISO2** в надёжном месте. Код даёт доступ к прогрессу; сервер не может его восстановить.
4. На другом устройстве укажите тот же адрес и код, нажмите «Проверить и восстановить». Игра проверит расшифрованное сохранение, покажет персонажа/контуры/зерно и предложит явно заменить локальный слот. До замены можно экспортировать текущий слот.

Каждая отправка — новый неизменяемый снимок и новый код. Автоматической синхронизации, обновления прежнего кода и объединения двух прохождений нет. Недоступность сервиса не отключает игру, IndexedDB или экспорт JSON. Код без адреса не определяет сервер. Без доступного Web Crypto интерфейс объясняет ограничение; обычное сохранение работает.

## Локальная проверка сервиса

Требуется Node.js 20+ только на машине сервиса. Из корня проекта:

```powershell
npm run cloud
```

По умолчанию: `http://127.0.0.1:8787`, файлы в `output/cloud-snapshots/`, до 100 копий и 128 МиБ. Каталог приватный, исключён из Git и релизного ZIP. Это локальный тест, не облако на другом устройстве. Игра с `npm start`/`npm run dev` на `http://127.0.0.1:4175` и штатный локальный Windows-запуск на портах 8765–8795 разрешены CORS по умолчанию. Origin `null` (`file://`) не разрешён: для сетевых копий используйте локальный сервер игры; автономный HTML остаётся пригоден для игры/JSON.

Настройки процесса, без изменения игры:

```powershell
$env:ISOBARA_CLOUD_DIR = 'D:\IsobaraPrivateBackups'
$env:ISOBARA_CLOUD_PORT = '8787'
$env:ISOBARA_CLOUD_HOST = '127.0.0.1'
$env:ISOBARA_CLOUD_ORIGINS = 'https://game.example.org,http://127.0.0.1:4175'
node tools/cloud-server.mjs
```

## Удалённый сервис

Сервис можно разместить отдельно на постоянной машине за HTTPS reverse proxy. Нужны стабильный адрес, постоянный приватный диск, резервирование этого диска, ограничение размера/частоты запросов на прокси и явный список игровых origin. CORS ограничивает браузерные обращения, **не является аутентификацией клиента**. Встроенный сервис предназначен для личного/ограниченного использования: перед открытием публичного приёма файлов нужны отдельная модель доступа и эксплуатационная защита от заполнения квоты. Публичное размещение, TLS и восстановление диска в этом задании не проверялись.

Протокол: `PUT /snapshots/<64 hex>` создаёт запись один раз (201); повтор даёт 409. `GET` возвращает зашифрованный JSON. Изменения и DELETE отсутствуют. Сервер ограничивает размер тела до 8,2 МБ, число одновременных операций и общий объём; при заполнении отвечает 507 без удаления прежних копий. Автоудаления по сроку нет. Администратор определяет срок хранения и очищает каталог осознанно; сообщите игрокам эту политику до использования.

Секрет содержит 128 случайных бит; четыре дополнительных hex-символа — контроль опечатки, а не криптографическая подпись. SHA-256 с разными префиксами выводит locator и ключ AES-GCM, nonce 12 байт генерируется заново. Сервер видит ciphertext и locator, но не код/ключ. Он всё ещё контролирует доступность файлов: шифрование не гарантирует вечное хранение. JSON-экспорт остаётся независимой резервной копией.

## Проверки разработчика

`npm test` включает криптографический roundtrip, повреждённые данные, неверные коды, неизменяемость, CORS, пределы и параллельную запись. `tests/revision_browser_test.py` проверяет ручной upload/download через DOM, ошибку адреса и подтверждение импорта. Для него нужны dev-сервер, локальный companion и Python Playwright; это тестовый контекст с импортированными fixtures, не настоящий пользовательский слот.
