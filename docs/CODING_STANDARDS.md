# Стандарты работы над ИЗОБАРОЙ

<a id="scope"></a>

## Границы изменений

Развивать существующую одиночную 3D action-RPG локальными изменениями. Сохранять 3D-мир и камеру, текущий локальный движок, авторское художественное оформление, подключённые изображения, совместимость сохранений и автономный запуск. Программные 3D-модели являются действующим оформлением игры.

Общая просьба «работать по roadmap/README» разрешает выполнение выбранного пакета в существующей игре. Смена движка, переписывание игры с нуля, переход к 2D, удаление ассетов или замена существующей графики примитивами, заглушками либо CSS-рисунками допустимы только по отдельному явному поручению владельца.

## Маршрут чтения

До правок прочитать все разделы, указанные для задачи. В смешанной задаче применять все подходящие строки таблицы.

| Задача | Обязательное чтение |
|---|---|
| Код, игровое поведение, сборка или игровые изображения и 3D-модели | [Контекст игры](#code-context) |
| Выполнение пакета roadmap или общая просьба «работать по README/roadmap» | [Контекст игры](#code-context) и [работа по roadmap](#roadmap-context) |
| Документация и отчёты evidence, включая описания ассетов | [Контекст документов](#docs-context) |
| Ассеты, их состояние или история; материалы `docs/asset-production/`, `evidence/asset-audit/` или `output/assets/` | [Ассеты и архив](#assets) |
| Любые изменения | [Проверки](#verification) |

Работу по выбранному пакету или общей просьбе «работать по README/roadmap» вести по [порядку работы в roadmap](../roadmap.md#1-как-использовать-документ). Статус, зависимости и критерии приёмки брать из выбранного пакета и таблицы статуса этого документа.

<a id="docs-context"></a>

## Контекст документов

[README](../README.md), [архитектуру](ARCHITECTURE.md) и конкретный пакет [roadmap](../roadmap.md) читать, когда правка затрагивает их положения. Обычная правка документации не требует выбора игрового пакета. Для отчётов и состава evidence применимы [правила хранения свидетельств](../evidence/README.md).

<a id="assets"></a>

## Ассеты и архив

[ASSETS.md](../ASSETS.md) описывает текущий каталог. [docs/asset-production/](asset-production/), [evidence/asset-audit/](../evidence/asset-audit/) и результаты в `output/assets/` — архив завершённого производства и свидетельства происхождения, а не очередь работ. Исторические замечания не являются дефектами текущих файлов.

<a id="verification"></a>

## Проверки

- Код, игровое поведение, сборка и игровые ассеты: выполнять подходящие проверки из [README](../README.md); если выбран пакет roadmap, также выполнять его проверки и критерии приёмки.
- Документация и отчёты: проверять ссылки, согласованность и diff. Если изменены только документы, пересборка игры не требуется.

Указывать фактически выполненные проверки и ограничения.
